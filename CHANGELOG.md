## v1.1.0 — 2026-11-18

Мульти-провайдерный роутер, три вида авторизации, журнал запросов со статистикой и провайдер
Claude по подписке через официальный Claude Code CLI.

### Новые возможности

- **Провайдер `claude-cli`: Claude по подписке.** Тип `claude-cli` запускает официальный Claude
  Code CLI как модель-клиент на один запрос. Клиент говорит обычным Anthropic-форматом
  (`/v1/messages`), история передаётся кадрами `stream-json`, ответ транслируется в SSE с
  настоящими дельтами текста и reasoning. Для Codex/Responses работает общий обратный конвертер
  (`convert_to_responses: true`), включая стрим.
- **Один upstream на клиентский запрос.** Приватный loopback-релей принимает только первое
  поколение; повторные попытки CLI отбиваются локально, поэтому подписка не списывается дважды.
- **Инертный инвентарь инструментов.** Флаг `--inert-mcp` (этот же бинарник) отдаёт модели имена
  и схемы инструментов, а любой `tools/call` отвечает `Denied`: инструменты исполняет только
  клиент.
- **Креды принадлежат CLI.** Вход выполняется нативным `claude auth login` в отдельный
  `CLAUDE_CONFIG_DIR`; aiproxy не читает, не хранит и не обновляет токен подписки.
- **Изоляция окружения дочернего процесса.** Белый список переменных: чужие `ANTHROPIC_*`
  отбрасываются, `HOME` подменяется пустым каталогом, прокси провайдера применяется явно, а
  loopback всегда исключён из прокси.
- **Корректный кэш промпта у `claude-cli`.** Постоянный `cwd` всех дочерних процессов,
  восстановление tool-result кадра до вида клиента и перенос единственного message-брейкпоинта
  на повторяемый контент — префикс хода N находится в ходе N+1.
- **Алиасы моделей Copilot (`model_aliases`).** Словарь в провайдере `copilot` подменяет имена
  моделей клиента на реальные модели Copilot для `/v1/responses` и `/v1/chat/completions`;
  встроенный алиас — `codex-auto-review → gpt-5.6-luna`, `{}` отключает алиасы.
- **`context_tier` для Copilot.** Поле `contextTier: "long_context"` добавляется в запросы к
  моделям с окном ≥ 500k токенов на `/v1/responses` и `/v1/chat/completions` (нативный
  `/v1/messages` его не принимает). Режимы: авто, `off`, принудительное значение.
- **Каталог моделей Copilot устойчив к смене биллинга.** Каталог запрашивается с заголовками
  `model-access`; если Copilot сообщает о переходе на оплату по использованию, запрос
  повторяется с токеном GitHub и идентичностью `copilot-developer-cli`.
- **Актуальный список моделей Anthropic:** Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5 — все с
  контекстом 1M.
- **Журнал: сводка на запрос, индекс и ретеншн.** Одна строка
  `logs/requests-YYYY-MM-DD.jsonl` + строка в `logs/index.sqlite` + `logs/errors-*.jsonl` для
  неуспешных запросов. Токены читаются из хвоста SSE (`message_delta`, финальный `usage`,
  `response.completed`), поэтому стримы больше не дают нулевой расход.
- **Тела в журнале режутся по краям.** Строка ограничена `AIPROXY_LOG_BODY_LIMIT` (32 КБ) и
  хранит начало и конец; середина заменяется маркером с числом вырезанных байт, JSON режется
  структурно и остаётся разбираемым. Правило общее для всех провайдеров, включая входящее тело
  клиента (`user→proxy`) и хопы `claude-cli` (`cli→relay`, `relay→upstream`).
- **Суточный бюджет тел.** `AIPROXY_LOG_BODY_BUDGET_MB` (512 МБ): когда выбран, тела перестают
  писаться до смены суток, сводки и ошибки продолжаются.
- **Потолок объёма журнала.** `AIPROXY_LOG_MAX_SIZE` (20G): при превышении удаляются самые
  старые суточные каталоги и сводки, пока дерево не впишется. Текущие сутки не удаляются.
  Уборка идёт в процессе (`AIPROXY_LOG_RETENTION_INTERVAL`, плюс проход на старте), cron не нужен.
- **Статистика и учёт.** `GET /admin/stats` (группировки `client`, `model`, `model_resolved`,
  `provider`, `task`, `profile`, `origin`, `status`, `error_code`, `reason`, `path`), `GET
  /admin/usage` (токены по клиентам и моделям), CLI-режимы `-stats` и `-backfill`.
- **Атрибуция запросов.** `client`, `profile`, `session_id`, `task`, `origin` в сводке
  (`X-Hermes-*`), `attempt`/`retry_of` по хешу тела, заголовки квоты провайдера в `ratelimit`,
  `X-Provider` и `X-Upstream-Model` в ответе.
- **Причина отказа в журнале.** `reason` при `upstream_called: false`: `unknown_model`,
  `provider_disabled`, `endpoint_not_supported`, `unauthenticated`, `upstream_error`.
- **Прокси на каждого провайдера, на обоих плечах.** `proxy_host` применяется к запросам
  `aiproxy → upstream`, к получению каталога моделей, к OAuth-обмену и (для `claude-cli`) к
  самому CLI. Прямого соединения в обход заданного прокси не бывает.

### Исправления

- **Системный промпт клиента доходит до модели у `claude-cli`.** Поле `system` верхнего уровня
  (так присылают Anthropic-клиенты) ставится перед текстом из сообщений `role: system` и уходит
  в `--system-prompt-file`; склейка детерминирована, лимит 4 МиБ.
- **Обрыв связи с Anthropic не превращается в «кончились кредиты».** `200` коммитится лениво, на
  первом содержательном событии: отказ upstream доходит своим статусом (`429`/`529`/`503`),
  оборванный стрим — `502`. Если контент уже ушёл, клиент получает терминальное событие `error`
  с машинной причиной и полем `status`, а не цитату Anthropic, которую хост может прочитать как
  вердикт о биллинге.
- **Reasoning виден клиенту.** Поле `thinking.display` пробрасывается в `CLAUDE_CODE_EXTRA_BODY`
  (на моделях 4.7+ по умолчанию `omitted`, и без него блоки приходили пустыми), а
  `signature_delta` доходит до клиента — многоходовое рассуждение не теряется.
- **Учёт расхода подписки.** Запись входящего запроса передаётся релею явно, поэтому в сводке
  есть `upstream_called: true`, токены и заголовки квоты подписки; служебные пробы CLI запись не
  затирают. `stream` в сводке описывает запрос клиента, а не хоп CLI → Anthropic.
- **Прокси нельзя обойти молча.** Невалидный `proxy_host` — отказ запуска; при мёртвом прокси
  upstream не получает ни одного запроса.
- **Входящий `Authorization` не уезжает на upstream** — вычищается вместе с `x-api-key`.
- **`read_idle_seconds` — пауза, а не бюджет запроса.** Долгая генерация с непрерывными дельтами
  не обрывается; границей остаётся контекст клиента.
- **Провайдер с одной моделью виден в `/v1/models`.**
- **`claude-cli` сохраняет нативные ID моделей** и в каталоге, и в маршрутизации.
- **Определение терминала у `claude-cli`** больше не принимает `/dev/null` за интерактивный
  ввод, поэтому вход не зависает в контейнере без TTY.
- **Путь upstream у релея не дублируется**, query-параметры (например `?beta=true`) сохраняются.
- **Сжатый ответ не превращается в мусор:** `Accept-Encoding` не пересылается, декомпрессию
  выполняет транспорт.
- **Гонка admission-релея:** слот занимается под тем же мьютексом, которым проверяется, пробы
  его не трогают.
- **Порядок блоков в ответе:** `thinking → text → tool_use`.
- **Мост Codex/Responses не паникует:** читатель и писатель делят один `sync.Once`, брошенное
  чтение разблокирует писателя.
- **Тело запроса ограничено 64 МиБ** в обработчике и релее; ответы upstream не усекаются по
  размеру клиентским таймаутом.
- **Статус middleware-отказов** (rate-limit, preflight) попадает в журнал и в статистику ошибок.
- **Конвертер Responses → Anthropic не теряет данные:** `instructions` → `system`,
  `parallel_tool_calls: false` → `disable_parallel_tool_use`, reasoning в стриме, устойчивость к
  неполному `usage` и незнакомым событиям, гарантированное завершение потока, отбрасывание
  неподдерживаемых инструментов с предупреждением, `refusal`, `input_file`, URL-картинки,
  `metadata.user_id`.
- **Большие запросы проксируются целиком**, лимиты применяет провайдер.
- **`vision` у DeepSeek** соответствует реальности.
- **Выключенный `copilot`** отвечает `provider copilot is disabled` с `reason:
  provider_disabled`, а не непрозрачным `500`.

### Изменения поведения

- **`providers.json` обязателен.** Env-переменных для отдельных провайдеров нет.
- **`supported_endpoints` не задаётся вручную** — вычисляется из `type` и флагов конвертации.
- **Типы провайдеров:** `copilot`, `messages`, `responses`, `chat`, `claude-cli`; значения
  `type` и флаги `convert_to_responses` / `convert_to_messages` — единственный способ описать
  формат upstream.
- **`api_key` и `auth: "oauth"` взаимоисключающие**, как и `context_tier`/`model_aliases` у
  не-copilot провайдера.
- **Провайдеру `claude-cli` нужен статический список `models`:** у CLI нет эндпоинта каталога.

## v1.0.0 — 2026-07-06

Форк [copilot2api](https://github.com/whtsky/copilot2api) v0.4.0 с мульти-провайдерной
архитектурой.

### Новые возможности

- **Мульти-провайдерная архитектура.** Все провайдеры описываются в `providers.json`; маршрут
  выбирается по префиксу ID модели, зашитых путей под конкретного провайдера нет.
- **Обобщённый роутер.** Единый `providers.Config` обслуживает `/v1/messages`,
  `/v1/chat/completions` и `/v1/responses`; `copilot-*` идёт в Copilot-транспорт, остальные
  модели — к своему провайдеру.
- **Агрегация `/v1/models`.** Объединённый каталог всех включённых провайдеров с capabilities:
  лимиты контекста и вывода, стриминг, tool calls, vision, reasoning effort.
- **OAuth-провайдеры.** GitHub Copilot (device flow) и OpenAI (device flow), плюс статические
  API-ключи; токены хранятся в каталоге токенов и обновляются автоматически.
- **Конвертация форматов на Go.** Anthropic Messages ↔ OpenAI Responses ↔ OpenAI Chat
  Completions, включая стриминг.
- **Адаптеры провайдеров.** Интерфейс `Adapter` для провайдер-специфичных правок;
  `DeepSeekAdapter` раскрывает MCP namespace-инструменты и нормализует имена моделей.
- **Прокси на каждого провайдера.** `proxy_host` с поддержкой `http`, `https`, `socks5`,
  `socks5h`.
- **Health-эндпоинт** `/health` со статусом и числом провайдеров.
- **Middleware.** Request ID, CORS, логирование задержек, лимитер на IP.
